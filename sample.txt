# 你不知道的 Agent

## 原理、架构与工程实践

暖米纸底，油墨蓝点缀。这是一份关于 AI Agent 的技术分享，适合用 Kami 设计系统排版后阅读。

## Agent 的定义

Agent 是一个能够感知环境、做出决策并执行行动的自治系统。在 LLM 时代，Agent 以语言模型为核心，通过工具调用、记忆管理和多步推理来完成复杂任务。

工具调用是 Agent 区别于普通 Chatbot 的关键——它不只是回答问题，而是实际去做事：搜索网页、读写文件、发送邮件、控制设备。

> 真正的 Agent 不是"会说话的模型"，而是"会做事的模型"。

## 核心架构

### 感知层

感知层负责从环境中收集信息。在软件 Agent 中，这包括用户输入、系统状态、工具执行结果、外部 API 返回等。所有信息经过格式化后进入上下文窗口。

### 推理层

推理层是 Agent 的大脑。LLM 基于上下文进行推理，决定下一步行动。关键挑战在于：上下文窗口有限，如何在长对话中保持有效记忆？

### 执行层

执行层将推理结果转化为实际行动。包括：工具调用（function calling）、代码执行（code interpreter）、外部 API 交互。执行结果反馈回感知层，形成闭环。

## 设计决策

- 工具粒度：单一职责 vs 多功能组合
- 记忆策略：全量保留 vs 摘要压缩 vs 滑窗遗忘
- 错误处理：自动重试 vs 降级方案 vs 人工介入
- 安全边界：沙箱执行 vs 权限确认 vs 操作日志

## 实践建议

---

- 从简单场景开始，逐步增加复杂性
- 给 Agent 明确的角色和约束
- 工具文档要写得像 API 文档一样清晰
- 日志是调试 Agent 的唯一手段
- 成本控制要前置，不要事后补救

```
// Agent 设计哲学
role      = specialist → generalist
tools     = few & sharp → many & dull
memory    = relevant > complete
safety    = deny by default
feedback  = fast > perfect
```

▲ 构建 Agent 系统的五条黄金法则。

## 未来趋势

Agent 正在从实验品走向生产环境。多 Agent 协作、自主编程、持续学习是接下来的三大方向。但无论技术如何演进，一个好的 Agent 永远是：**理解上下文、知道边界、能交付结果**。
